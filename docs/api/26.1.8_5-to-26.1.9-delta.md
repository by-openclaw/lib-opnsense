# OPNsense API schema delta: 26.1.8_5 → 26.1.9

Field-level diff of the 34 `*__schema.json` files that differ between
`docs/api/data/26.1.8_5/` and `docs/api/data/26.1.9/`.

## Method

Each `<entity>__schema.json` is the empty `get_<entity>` response: a single
root-wrapper key (e.g. `alias`, `rule`, `subnet4`) whose value is the dict of
**model field definitions**. A field is either a scalar default (string) or an
enum (a dict of `{option: {value, selected}}`).

The diff strips two classes of noise before reporting:

1. **`selected` flips and option ordering** — runtime state, not schema.
2. **Dynamically populated option lists** — these schema probes were captured on
   two *different* firewalls: 26.1.8_5 on a near-empty box, 26.1.9 on the fully
   provisioned prod FW. So nearly every "difference" is just config that now
   exists on prod being offered as selectable options: the 13 `optN` interfaces
   (`LAN_TRUNK`, `MGMT`, `DMZ`, … `WAN_TELENET`), the full alias content list,
   the WAN gateways (`WAN_PROXIMUS_PPPOE`, `WAN_TELENET_GW`, …), UUID-keyed
   alias/overload pickers, monit `depends`/`tests` references, and the
   `auth-group` privilege list gaining `page-services-*` entries from installed
   plugins (CrowdSec, chrony, lldpd, dnscrypt-proxy, qemu-guest-agent, acme).
   None of these are new **fields**; they are populated values of existing enum
   fields (`interface`, `content`, `gateway`, `replyto`, `overload`, `depends`,
   `tests`, `priv`). They do **not** require model changes.

The only thing that matters for extending lib managers/models is **new or removed
top-level model field keys** (and genuinely new *static* enum options on an
existing field). The script compared `set(inner.keys())` for every pair.

## Real new fields (the only model-affecting changes)

### kea4-reservation → `+next_server`
- Field: `next_server` (scalar string, default `""`).
- TFTP/PXE "next server" address per reservation.
- Not present in `models/dhcp/kea4_reservation.py` → **gap**.

### kea4-subnet → `+allocator`
- Field: `allocator` (enum), options:
  - `""` → `Default` (selected by default)
  - `iterative` → `Iterative`
  - `random` → `Random`
  - `flq` → `Free Lease Queue`
- Kea lease-allocation strategy per subnet.
- Not present in `models/dhcp/kea4_subnet.py` → **gap**.

### kea6-subnet → `+dynamic_prefix`, `+option_data_autocollect`
- `dynamic_prefix` (scalar, default `"0"`) — boolean-style flag.
- `option_data_autocollect` (scalar, default `"0"`) — boolean-style flag.
- Neither present in `models/dhcp/kea6_subnet.py` → **gap**.

## Note on auth-group `priv` enum

The 6 added `priv` options are not core OPNsense schema growth — they are
privilege strings contributed by **plugins installed on the prod FW**
(dnscrypt-proxy, ACME client, chrony, lldpd, qemu-guest-agent, CrowdSec). They
will appear on any firewall with those plugins and disappear without them. The
`page-diagnostics-backup-restore` label also changed text
("Diagnostics: Backup / Restore" → "System: Configuration: Backups"), a UI
relabel, not a key change. `models/auth/group.py` stores `priv` as a free list of
strings, so no model change is required; this is informational only.

## Conclusion

- **No new manager is required for 26.1.9.** No schema gained or lost an endpoint,
  and no schema introduced a field that lacks an existing owning manager/model.
- **Real field gaps worth a follow-up: 3 schemas, all in the Kea DHCP scope**
  (LOWER roadmap priority — keep-Kea is the final decision, NetBox uses the Kea
  source):
  - `models/dhcp/kea4_reservation.py` + `managers/dhcp/kea4_reservation.py` → add `next_server`
  - `models/dhcp/kea4_subnet.py` + `managers/dhcp/kea4_subnet.py` → add `allocator` (enum)
  - `models/dhcp/kea6_subnet.py` + `managers/dhcp/kea6_subnet.py` → add `dynamic_prefix`, `option_data_autocollect`
- **Every HIGH-relevance schema** (fw-alias, fw-filter-rule, fw-1to1/dnat/snat/npt,
  fw-group, ub-dnsbl, ub-host-alias, ovpn-instance, routing-gw, route, ipsec-conn,
  monit-service) has **no field-definition change** — all their diffs are
  populated runtime option lists (interfaces, aliases, gateways, UUID pickers)
  caused by capturing 26.1.9 on the configured prod FW vs an empty 26.1.8_5 box.
  No lib changes needed there for the upgrade.
