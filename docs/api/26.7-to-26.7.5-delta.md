# OPNsense API schema delta — 26.7 → 26.7.5 CE

> Captured with `scripts/probe-api-schemas.sh --scrub …` against a throwaway firewall built
> from the seed and updated to **26.7.5** (never the production appliance). Data:
> [`data/26.7.5/`](data/26.7.5/) vs [`data/26.7/`](data/26.7/). Analysis:
> `scripts/verify-validators.py --schema-dir docs/api/data/26.7.5 --baseline-dir docs/api/data/26.7`.

## Result

| Check | 26.7 | 26.7.5 |
|---|---|---|
| Endpoints probed / answering | 206 / 206 | 206 / 206 |
| Validator fields OK | 409 | 424 (15 new validators) |
| Enum mismatches | 0 | 0 |
| pylib fields missing from the schema | 2 | 0 |
| Firmware changes in managed entities | — | 24 (+ 23 option lists that differ only by device state) |

No endpoint was removed. Every change is additive except one rename that predates 26.7.5 and
was found by this pass (static routes, below).

## Ported in this change

| Entity | Change | Library |
|---|---|---|
| `routes/routes` | `disabled` was renamed `enabled` (inverted) at **26.7**. The manager sent `disabled`, which the API ignores: a route declared disabled was created **enabled**, and the diff never saw it. | `RtRouteManager` accepts either flag and sends the one the firmware has (read from the schema once) — `ensure`, `create`, `update`. |
| `firewall/one_to_one` | The API field has been `enabled` on every probed firmware (25.1 → 26.7.5); the manager validated and sent `disabled`. Same silent effect. | `FwOneToOneManager` translates the legacy `disabled` input to `enabled`. |
| `diagnostics/netflow` | `setconfig` saves (`{"result": "saved"}`) and names the field on a validation failure. | New `NetflowSettingsManager` (`getconfig` / `setconfig` / `reconfigure`) — the capture configuration no longer has to be written by the seed. `BaseSingletonManager` gained `_get_action` / `_set_action`. |
| `firewall/filter` | `max-pkt-rate-number`, `max-pkt-rate-seconds`, `received-on`, `received-on-not` | validators added |
| `firewall/source_nat` | `endpoint-independent`, `poolopts` (enum), `poolopts_sourcehashkey` | validators added |
| `interfaces/gif_settings` | `noclamp` | validator added |
| `kea/dhcpv4` subnet | `ping_check`, `subnet_id` | validators added |
| `kea/dhcpv6` subnet | `subnet_id` | validator added |
| `wireguard/client` | `privkey` | validator added, **redacted** |
| `wireguard/server` | `allowed_ips` | validator added |

## Not ported (nothing to do in the library)

- `audit` (dict: `created`, `updated`, `userdata`) on filter, DNAT, source NAT, 1:1 and NPT rules —
  read-only metadata; DNAT's former top-level `updated` moved under it. The diff only compares
  the fields a caller passes, so the block is ignored.
- `auth/user`: `menu_favorites` — a GUI preference.
- IPsec: post-quantum proposals (`…-ke1_mlkem768`, `…-ke1_mlkem1024`); trust: key type `7680`.
  The library does not enumerate these options, the API validates them.

## Seed boundary on 26.7.5 (what still has no API)

| Area | API on 26.7.5 | Can leave the seed |
|---|---|---|
| NetFlow capture / local collection | `diagnostics/netflow/{getconfig,setconfig}` | **Yes** — `NetflowSettingsManager` |
| Interface assignment | `interfaces/assignment/*` — `identifier`, `if`, `descr`, `lock` only | No — the address configuration of an interface (static / DHCP / PPPoE) has no API; an assignment without it is not a usable interface |
| Interface hardware settings | `interfaces/settings/{get,set}` | Not in the seed today (defaults) |
| System identity (hostname, domain, resolvers, timezone), sshd, sudo | none | No |
| Users and groups | `auth/user`, `auth/group` (already managed) | Technically yes; the break-glass accounts are a boundary decision, not a library gap |
